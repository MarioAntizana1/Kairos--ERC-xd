# ADR-0003 — Usar Nav2 como pila de navegación

> Estado: Aceptada · Fecha: 2026-11-21 · Responsable: Navegación · Reemplaza a: —

## Contexto

El demo necesita localización, planificación global, control local, evitación de obstáculos, recuperación y una interfaz estándar para enviar objetivos. Construir esto desde cero consumiría el tiempo del equipo y añadiría riesgo.

## Alternativas consideradas

| Alternativa | Ventajas | Desventajas | Madurez | Veredicto |
|---|---|---|---|---|
| **Nav2** | Estándar de ROS 2; AMCL, Navfn, RPP, costmaps, behaviors; documentación | Configuración extensa; dependencia de la API | Alta | **Elegida** |
| Stack propio | Control total; aprendizaje profundo | Mucho esfuerzo; menos pruebas; riesgo alto | Baja | Descartada |
| ArduPilot + MAVROS | Robusto en vehículos; ecosistema | Orientado a vuelo/UGV; integración ROS 2 menos directa | Alta | Descartada |
| ROS 1 `move_base` | Conocido | EOL; no ROS 2 | Baja | Descartada |

## Decisión

Usar **Nav2** con:

- **AMCL** para localización sobre mapa estático.
- **Navfn** para planificación global.
- **Regulated Pure Pursuit (RPP)** para control local (bajo CPU).
- **Costmaps** con capa estática, obstáculos e inflación.
- **BT Navigator** con el árbol por defecto.

## Consecuencias

### Positivas

- Interfaz estándar `NavigateToPose`, fácil de integrar y de reemplazar.
- Componentes probados y documentados.
- Recuperación incorporada (spin, backup, wait).
- Ruta de escalado a Smac, MPPI, route server, docking.

### Negativas

- Muchos parámetros; el tuning requiere tiempo.
- MPPI (por defecto en Jazzy) es pesado para el Pi; se usa RPP.
- La API puede cambiar entre distros.
- El árbol de comportamiento por defecto puede ser conservador.

### Neutrales

- La lógica de misión queda fuera de Nav2, en un nodo propio, para no acoplarse al BT.

## Mitigaciones

- Empezar con la configuración oficial de Jazzy y adaptar solo lo necesario.
- Documentar cada parámetro modificado y su motivo.
- Pruebas de integración con un goal simple antes de la misión completa.
- Mantener el nodo de misión como capa fina sobre la acción.

## Criterios de revisión

- Si Nav2 no cumple los RNF de éxito o precisión tras el tuning.
- Si el CPU del Pi no sostiene la pila.
- Si se necesita cinemática Ackermann o navegación 3D.
- Si una versión futura rompe la interfaz.
